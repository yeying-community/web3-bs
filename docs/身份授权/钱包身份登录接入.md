# 钱包身份登录接入

本文面向 DApp 开发者。Wallet Identity 是独立于 SIWE 的身份授权协议；需要 Ethereum 地址控制权时，再单独调用 `loginWithSiwe`。

## 钱包身份登录接口

应用使用 `loginWithWalletIdentity` 完成应用层登录：SDK 获取后端 session，向 Wallet 请求身份 Presentation，并把结果提交给后端验证。

```ts
import { loginWithWalletIdentity } from '@yeying-community/web3-bs'

const result = await loginWithWalletIdentity({
  provider,
  baseUrl: 'https://app.example/api/auth',
  scopes: ['identity.basic', 'identity.username', 'identity.email'],
})
```

`loginWithWalletIdentity` 不读取当前选中账户，也不要求当前选中账户与身份绑定地址一致。只有应用在 session scope 中明确请求 `identity.wallet` 时，Presentation 才包含身份已有的地址绑定证明。

后端必须为每次登录生成新的 `audience`、`nonce`、scope 和有效期，并验证 Presentation 的 DID 签名、上下文及凭证。SDK 不会自动调用 SIWE、读取 `eth_accounts` 或执行地址绑定签名。

## 自定义流程

需要自定义会话、非 JWT 响应或非 Node 身份服务时，直接使用 `requestIdentityPresentation`：

```ts
const presentation = await requestIdentityPresentation({
  provider,
  audience: session.audience,
  nonce: session.nonce,
  scopes: session.scopes,
})
await appBackend.verifyPresentation(presentation)
```

## 账户和 SIWE

身份 scope 不授予 `eth_accounts`。需要交易或当前账户读取时，DApp 单独调用 `eth_requestAccounts`；需要 SIWE 时调用 `loginWithSiwe`。`identity.wallet` 要求 Presentation 返回经 Node 签发并由服务端验证的 `WalletAccountCredential`，证明 DID 和地址已建立关联，但不代表账户访问权限或当前地址控制权。Wallet 会从当前身份的有效绑定凭证中确定 `walletProof`，不要求当前选中的账户就是绑定地址。

## 错误处理

应用应向用户展示明确错误：用户拒绝、钱包锁定、scope 缺少凭证、Presentation 过期、audience/nonce 不匹配和凭证未验证。错误码见社区钱包的[钱包错误码](https://github.com/yeying-community/wallet/blob/main/docs/协议规范/钱包错误码.md)。

相关 Wallet 规范：[钱包身份协议](https://github.com/yeying-community/wallet/blob/main/docs/协议规范/钱包身份协议.md)。
